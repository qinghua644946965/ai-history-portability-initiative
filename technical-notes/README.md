# 技术讨论边界

**中文** | [English](README.en.md)

配套于 Initiative Draft v0.1。本目录记录待讨论问题，不构成协议、标准或现有产品能力说明。

## 最低能力与未定实现

| 诉求 | 应解释的问题 | 本版不规定 |
| --- | --- | --- |
| 用户授权与只读访问 | 谁授权、范围是什么、如何撤销 | 具体认证协议 |
| 分页 | 如何继续、何时结束、数据变动是否影响遍历 | 页面大小与端点 |
| 稳定增量定位 | 如何恢复、去重、识别更新；游标失效如何重建 | 游标编码与统一 JSON |
| 范围说明 | 消息、任务状态、可见工具结果、附件与产物覆盖情况 | 统一内部数据模型 |
| 运行约定 | 限流、重试、保留期限与变更通知 | 固定 QPS 或实时承诺 |

“稳定”不意味着游标永不过期；过期条件和恢复路径需要可理解。“只读”描述访问能力，不代表接收工具天然可信。

## 后续问题

- 稳定标识与更新时间如何支持可重复读取，避免重试产生重复记录？
- 长历史分页时发生新增、编辑或删除，如何报告一致性边界？
- 删除通知如何与不保留已删除正文相容？哪些历史变化无法回溯？
- 分支、消息编辑、任务产物和附件失效链接如何保留必要关系？
- 用户撤销授权后，已获取副本由谁负责管理？
- 如何说明数据未提供、已过期、无权限和暂时失败之间的区别？

可接受服务商原生格式加用户侧适配器。可靠性与成本可分阶段讨论；本版不提供伪造 API 示例或声称某厂商已经支持这些能力。
